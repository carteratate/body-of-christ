# P1b adapter fixes: Catechism, Summa, Church Fathers, medieval

29 September 2026. Work specifications for plan items 1.6, 1.7, 1.8a, 1.8b, 1.8c, 1.8d, 1.8e and 1.9. The plan is `docs/2026-09-28-corpus-cleanup-plan.md` and its decision log is settled. Nothing here changes a decision.

## Overview and recommended order

1. Every item here changes adapter output only. None of it reaches production until the P4 republish, because the publish lock (0.4) merges first.
2. Every item depends on 0.4 (publish lock), 2.1 (frozen document IDs and structural anchors), 0.1a and 0.1c (coverage tests and release report with the remap diff), and 1.10 (shared text hygiene, including note stripping).
3. Order: 1.8d Athanasius first, because the live text is a copyrighted translation and the fix is small.
4. Then 1.6 Catechism and 1.7 Summa. Both are self-contained single-document adapters.
5. Then 1.8a ANF editorial strip, after research R4 closes. It creates the shared `ingest/editorial.py` module that 1.8b and 1.8c reuse.
6. Then 1.8b NPNF Augustine strip, which needs one decision from Carter about splitting the two treatise volumes into works.
7. Then 1.8c Fathers labels, authors, greetings and the Ignatius recension split. It goes on the same long-lived branch as the P3 splits (3.1 removals), as the plan says. No other item here needs that branch.
8. 1.8e is a decision, not a PR. The Fathers adapter silently drops about 30 whole works, and adding them back needs a rule A to H check per work.
9. 1.9 medieval goes last, after R5 closes. It also owns two shared label helpers in `ingest/thml_doc.py`, so its release report shows about 64 Fathers label changes with no content change.
10. Measurements come from running each adapter on master (commit 5475c49) against the vendored sources, plus read-only queries on the live database on 29 September 2026.

A note on measurement. Master's adapters no longer match what production holds. Catechism builds 809 passages against 800 live, the Summa 26,792 against 26,750, medieval 449 against 434. Fathers match at 9,783. Every release report must diff against live, not against an earlier local build.

### 1.6. Catechism adapter fixes

- **Type:** PR
- **Depends on:** 0.4, 2.1, 0.1a, 0.1c, 1.10
- **Goal:** Readers see the 2018 text of CCC 2267 on the death penalty. Sentences no longer start with a lowercase "the" or "and". The reader's contents list shows Part, Section, Chapter and Article headings instead of 29 buckets named "CCC §§0–99". Each passage shows where each numbered paragraph starts, and its citation names the paragraphs it actually holds, with no "(part)".
- **Current state:**
  - Source is `sources/catechism/ccc.json` (nossbigg/catechism-ccc-json v0.0.2, created 2019-08-29). Its paragraph for 2267 sits in page node `toc-305` and holds the 1997 text ending "very rare, if not practically non-existent." Live has 1 passage containing that phrase, anchor `ccc/2266`, reference "CCC §2266–2267 (part)".
  - Lowercase starts come from the source file, not the adapter. After a sentence end, and excluding ellipses and abbreviations, the source has 569 sentences starting "the" and 60 starting "and". Examples are "from the councils. the Council of Trent is a noteworthy example" (CCC 9) and "faithfulness. and so we can understand" (CCC 1062). Another 35 lowercase "the" follow an ellipsis inside quotations, which is correct and must stay. Twenty-two text elements start with "the" after a list break, as in the Creed and the Confirmation prayer. Those are list items and must stay. Only 17 other lowercase sentence starts exist, such as "or" 4 and "because" 2, and I did not check them. Live shows the "the" pattern in 332 passages. The plan's 509 sentences in 310 passages used a narrower pattern.
  - Chapter labels come from `chapter_no = first // 100` at `ingest/catechism.py:266` and the label at line 279. That gives 29 numeric chapters, confirmed live with `count(distinct chapter_label) = 29`.
  - "(part)" comes from `make_reference(..., is_partial=n_sections > 1)` at line 200. It fires whenever a large node splits at headers, even though each section carries its own paragraph list, so the suffix is wrong. Pieces from `split_display_passage` at line 268 reuse the node's reference too. There are 498 "(part)" references in adapter output and 496 live. 118 passages are split pieces that share a reference with a sibling.
  - Paragraph numbers are dropped. `_para_text` at line 46 keeps only `type == "text"` elements, so the `ref-ccc` element that carries the number never reaches the text.
  - The TOC exists in the source. `toc_link_tree` gives the hierarchy, and `toc_nodes` gives each node's heading text and indent level. Levels are uneven: Part at 1, Section or Chapter at 2 to 3, Article at 3 to 4, with sub-heads at 4 to 5. Grouping page nodes under their nearest Article, Chapter, Section or Part ancestor gives about 96 chapters. That number is an estimate from a quick script.
- **Changes:**
  - In `ingest/catechism.py`, add `fix_sentence_case(text: str) -> str`. Apply it per `text` element inside `_para_text`. It capitalizes `the` and `and` when they follow `[.!?]`, then optional closing quotes or brackets, then whitespace. It skips when the preceding token ends in an ellipsis (`. . .`, `...`, `....` or the ellipsis character), and when the preceding token is an abbreviation from a fixed list (`cf.`, `Cf.`, `St.`, `i.e.`, `e.g.`, `Hom.`, `Ex.`, `etc.` and the Bible-book abbreviations). Never touch the first word of an element. Keep it Catechism-only, because the defect belongs to this source file.
  - CCC 2267. Vendor a small override file `sources/catechism/overrides/ccc-2267-2018.json` holding the official English text, its footnote, the source URL `https://press.vatican.va/content/salastampa/en/bollettino/pubblico/2018/08/02/180802a.html`, the retrieval date and a sha256. The text begins "Recourse to the death penalty on the part of legitimate authority" and ends "for its abolition worldwide." Record the file in `scripts/vendor_sources.py`'s catechism manifest so 0.2's source hashes cover it. In `extract_node_text` and `split_large_node`, replace the `text` elements of the paragraph whose `ref-ccc` is 2267 with the override. Keep the 1997 text in passage metadata as `superseded: [{"paragraph": 2267, "text": ..., "in_force": "1997 to 2 August 2018", "source": "ccc.json v0.0.2"}]`, so 2.4b can show it as labeled history under rule F. Metadata isn't embedded or indexed, so the old text stays out of search.
  - Paragraph numbers. When a paragraph starts with a `ref-ccc` element, prefix its text with `§2267 `. Use the same `§N` form that `unit_label` already uses. The marker becomes searchable as a token, which helps exact-paragraph queries.
  - References. Compute each emitted piece's paragraph list from the markers inside that piece, plus the paragraph that is continuing when the piece opens mid-paragraph. Reference is `CCC §N` or `CCC §N–M` or `CCC §N, §M`. Drop the `is_partial` argument and the "(part)" suffix. If two pieces of one long paragraph remain identical, append ` (1 of 2)` style counters. Expect only a handful of these.
  - Chapters. Build a parent map over `toc_link_tree`. For each page node, pick its nearest ancestor whose heading matches `^(PART|SECTION|CHAPTER|Article|ARTICLE)` or the Prologue node. `chapter_key = anchor("ccc", *path)`, with path segments like `part-3`, `section-2`, `chapter-2`, `article-5`. `chapter_label` is the heading path in title case, for example "Part Three, Section Two, Chapter Two, Article 5, The Fifth Commandment". Take the words from `toc_nodes[...]["text"]`, converted with `normalize.caps.smart_title_case`.
  - Keep passage anchors as they are, `ccc/<first paragraph>` plus `-pN` for split pieces, so bookmarks keep resolving.
  - Fixture. Add `tests/fixtures/ccc_min.json`, a cut-down source with one large node that splits at headers, one node holding 2267, and one sentence of each lowercase case including an ellipsis case, so the unit tests run in GitHub Actions without vendored sources.

  - Source check, run locally from `tests/test_catechism_passages.py`. At most 5 lowercase "the"/"and" sentence starts remain outside ellipses. Anchors stay unique. Every live anchor except split-piece anchors still exists in the build.
  - Manual check listed in the PR. Compare 30 randomly chosen corrected sentences against vatican.va's `ENG0015` pages and record each result. If any "and" case is lowercase on vatican.va, remove "and" from the rule.

Passage anchors stay first-paragraph based, so the 4 bookmarks and most of the 307 retrievals on Catechism passages keep their IDs. That makes "Objection 4: On the contrary, ..." an objection whose body starts "On the contrary, ...", which fixes the 21 cases without touching the text. Unmarked paragraphs join the current part. One exception applies. When the current part is "On the contrary" and the article has no bold "I answer that" anywhere, the first unmarked paragraph after the sed contra starts an "I answer that" part. N", "On the contrary" gives "sed contra", "I answer that" gives "co." and "Reply to Objection N" gives "ad N". A part split into several pieces gets " (1 of 3)". The result is "Summa Theologiae I, q. 29, a. 2, obj. 4". Put the clean part name, such as "Second Part of the Second Part", into metadata `part` instead of the current string.
  - Anchors. Keep the existing `f"{ch_key}/{sub}"` scheme unless 2.1 defines Summa anchors differently. The paragraph walk changes `sub` numbering only inside the articles it repairs, roughly 21 + 4 + 1 articles. The release report lists them.
