# P1b adapter fixes: Catechism, Summa, Church Fathers, medieval

**Before implementing any item in this file, follow `README.md` in this folder. It says to ask Carter the item's open questions first, record the answers, and update other specs only in the ways it allows.**

29 September 2026. Work specifications for plan items 1.6, 1.7, 1.8a, 1.8b, 1.8c, 1.8d, 1.8e and 1.9. The plan is `docs/2026-09-28-corpus-cleanup-plan.md` and its decision log is settled. Nothing here changes a decision.

## Overview and recommended order

1. Every item here changes adapter output only. None of it reaches production until the P4 apply, because the publish lock (0.4) merges first and nothing touches live data before then (D7). The one possible exception is retiring On the Incarnation early (1.8d), if Carter approves.
2. Every item depends on 0.4 (publish lock), 2.1 (frozen document and passage IDs, structural anchors, removal registry), 0.1a and 0.1c (coverage tests and release report with the remap diff), and 1.10 (shared text hygiene, including note stripping, trailing author periods in 1.10a, and the split-piece citation helper in 1.10c).
3. Removals. Everything an item here removes (editorial passages, split-off notes, duplicate text, other authors' commentary, a superseded translation) is recorded by anchor in 2.1's removal registry in the same PR, with reason and tombstone text (D4). Nothing is deleted; the P4 apply retires what the registry lists (D2, D3).
4. Identity. Passage IDs come from 2.1's frozen passage registry, so a relabel or an anchor-string change keeps the ID (D1). Only genuinely new units get new IDs, and a unit whose identity changes (the split Ignatius recensions) gets a new ID plus a redirect from the old one.
5. Order, matching the plan's phase table: 1.6 Catechism and 1.7 Summa first. Both are self-contained single-document adapters, and both use 1.10c's citation helper.
6. Then 1.8a ANF editorial strip, after research R4 closes. It creates the shared `ingest/editorial.py` module that 1.8b, 1.8c and 1.8d reuse.
7. Then 1.8d On the Incarnation, which depends on 1.8a and on R6's check of the Robertson edition.
8. Then 1.8b NPNF Augustine strip, which needs one decision from Carter about splitting the two treatise volumes into works.
9. Then 1.8c Fathers labels, authors, greetings and the Ignatius recension split. It is an ordinary PR; container works are modelled with `work_key` and `document_works` (D6), so there are no P3 splits and no shared branch with 3.1.
10. 1.8e is a decision, not a PR. The Fathers adapter silently drops about 30 whole works, and adding them back needs a rule A to H check per work.
11. 1.9 medieval goes last, after R5 closes. It also owns two shared label helpers in `ingest/thml_doc.py`, so its release report shows about 64 Fathers label changes with no content change.
12. Measurements come from running each adapter on master (commit 5475c49) against the vendored sources, plus read-only queries on the live database on 29 September 2026.
13. D1 to D11 are the "Cross-cutting design decisions" in the plan. Where this file and those decisions disagree, the decisions win.

A note on measurement. Master's adapters no longer match what production holds. Catechism builds 809 passages against 800 live, the Summa 26,792 against 26,750, medieval 449 against 434. Fathers match at 9,783. Every release report must diff against live, not against an earlier local build.

A note on the task list. The request placed the Anselm, Boethius and Bernard fixes under 1.8c. I moved them to 1.9, because they live in `ingest/medieval.py` and the medieval manifest. If Carter prefers them in 1.8c, the spec text moves unchanged.

### 1.6. Catechism adapter fixes

- **Type:** PR
- **Depends on:** 0.4, 2.1, 0.1a, 0.1c, 1.10 (1.10c's `piece_reference` in particular)
- **Goal:** Readers see the 2018 text of CCC 2267 on the death penalty. Sentences no longer start with a lowercase "the" or "and". The reader's contents list shows Part, Section, Chapter and Article headings instead of 29 buckets named "CCC §§0–99". Each passage shows where each numbered paragraph starts, and its citation names the paragraphs it actually holds, with no "(part)".
- **Current state:**
  - Source is `sources/catechism/ccc.json` (nossbigg/catechism-ccc-json v0.0.2, created 2019-08-29). Its paragraph for 2267 sits in page node `toc-305` and holds the 1997 text ending "very rare, if not practically non-existent." Live has 1 passage containing that phrase, anchor `ccc/2266`, reference "CCC §2266–2267 (part)".
  - Lowercase starts come from the source file, not the adapter. After a sentence end, and excluding ellipses and abbreviations, the source has 569 sentences starting "the" and 60 starting "and". Examples are "from the councils. the Council of Trent is a noteworthy example" (CCC 9) and "faithfulness. and so we can understand" (CCC 1062). Another 35 lowercase "the" follow an ellipsis inside quotations, which is correct and must stay. Twenty-two text elements start with "the" after a list break, as in the Creed and the Confirmation prayer. Those are list items and must stay. Only 17 other lowercase sentence starts exist, such as "or" 4 and "because" 2, and I did not check them. Live shows the "the" pattern in 332 passages. The plan's 509 sentences in 310 passages used a narrower pattern.
  - Chapter labels come from `chapter_no = first // 100` at `ingest/catechism.py:266` and the label at line 279. That gives 29 numeric chapters, confirmed live with `count(distinct chapter_label) = 29`.
  - "(part)" comes from `make_reference(..., is_partial=n_sections > 1)` at line 200. It fires whenever a large node splits at headers, even though each section carries its own paragraph list, so the suffix is wrong. Pieces from `split_display_passage` at line 268 reuse the node's reference too. There are 498 "(part)" references in adapter output and 496 live. 118 passages are split pieces that share a reference with a sibling.
  - Paragraph numbers are dropped. `_para_text` at line 46 keeps only `type == "text"` elements, so the `ref-ccc` element that carries the number never reaches the text.
  - The TOC exists in the source. `toc_link_tree` gives the hierarchy, and `toc_nodes` gives each node's heading text and indent level. Levels are uneven: Part at 1, Section or Chapter at 2 to 3, Article at 3 to 4, with sub-heads at 4 to 5. Grouping page nodes under their nearest Article, Chapter, Section or Part ancestor gives about 96 chapters. That number is an estimate from a quick script.
- **Changes:**
  - In `ingest/catechism.py`, add `fix_sentence_case(text: str) -> str`. Apply it per `text` element inside `_para_text`. It capitalizes `the` and `and` when they follow `[.!?]`, then optional closing quotes or brackets, then whitespace. It skips when the preceding token ends in an ellipsis (`. . .`, `...`, `....` or the ellipsis character), and when the preceding token is an abbreviation from a fixed list (`cf.`, `Cf.`, `St.`, `i.e.`, `e.g.`, `Hom.`, `Ex.`, `etc.` and the Bible-book abbreviations). Never touch the first word of an element. Keep it Catechism-only, because the defect belongs to this source file.
  - CCC 2267. Vendor a small override file `sources/catechism/overrides/ccc-2267-2018.json` holding the official English text, its footnote, the source URL `https://press.vatican.va/content/salastampa/en/bollettino/pubblico/2018/08/02/180802a.html`, the retrieval date and a sha256. The text begins "Recourse to the death penalty on the part of legitimate authority" and ends "for its abolition worldwide." Record the file in `scripts/vendor_sources.py`'s catechism manifest so 0.2's source hashes cover it. In `extract_node_text` and `split_large_node`, replace the `text` elements of the paragraph whose `ref-ccc` is 2267 with the override. Keep the 1997 text of §2267 as its own history passage (rule F, D11), not as metadata: anchor `<anchor of the passage holding §2267>/history-1997` (today `ccc/2266/history-1997`), content "§2267 " plus the 1997 text, reference "CCC §2267 (1997 text, in force until 2 August 2018)", `searchable = False`, and `superseded_by_anchor` naming the passage that holds the 2018 text. 2.4b shows it in the reader as "earlier text". It is a Qdrant point with `searchable = false` (D5), so it stays out of search.
  - Paragraph numbers. When a paragraph starts with a `ref-ccc` element, prefix its text with `§2267 `. Use the same `§N` form that `unit_label` already uses. The marker becomes searchable as a token, which helps exact-paragraph queries.
  - References. Compute each emitted piece's paragraph list from the markers inside that piece, plus the paragraph that is continuing when the piece opens mid-paragraph. Build the string with 1.10c's `piece_reference` (in `ingest/pieces.py`), not a private copy: `CCC §N`, a range `CCC §N` to `M` in the helper's range form, or `CCC §N, §M`. Drop the `is_partial` argument and the "(part)" suffix. If two pieces of one long paragraph would still share a reference, the helper appends the settled suffix, for example "CCC §2267 (part 1 of 2)" (D5). Expect only a handful of these.
  - Identity. The passage holding §2267 keeps its ID; the 2018 text is the same numbered paragraph in its current form, so the passage sets `text_replaced: "2018 revision of CCC 2267"` for 0.1c's stability check. The 1997 text is kept as the history passage above, a new unit with a new ID; it is not a removal, so it has no removal-registry entry.
  - Chapters. Build a parent map over `toc_link_tree`. For each page node, pick its nearest ancestor whose heading matches `^(PART|SECTION|CHAPTER|Article|ARTICLE)` or the Prologue node. `chapter_key = anchor("ccc", *path)`, with path segments like `part-3`, `section-2`, `chapter-2`, `article-5`. `chapter_label` is the heading path in title case, for example "Part Three, Section Two, Chapter Two, Article 5, The Fifth Commandment". Take the words from `toc_nodes[...]["text"]`, converted with `normalize.caps.smart_title_case`.
  - Keep passage anchors as they are, `ccc/<first paragraph>` plus `-pN` for split pieces, so bookmarks keep resolving.
  - Fixture. Add `tests/fixtures/ccc_min.json`, a cut-down source with one large node that splits at headers, one node holding 2267, and one sentence of each lowercase case including an ellipsis case, so the unit tests run in GitHub Actions without vendored sources.
- **Acceptance checks:**

### 1.7. Summa adapter fixes

- **Type:** PR
- **Depends on:** 0.4, 2.1, 0.1a, 0.1c, 1.10c (`piece_reference` and the "(part 2 of 3)" form)
- **Goal:** Days five and six of creation, Part I questions 71 and 72, exist. No blank or near-empty cards appear. Each passage cites the part of the article it holds, for example "Summa Theologiae I, q. 29, a. 2, obj. 4", "…, sed contra", "…, co." and "…, ad 4".
- **Current state:**
  - Q71 and Q72 are "one article" questions. In `summa.xml` at lines 13451 and 13493, the article text sits directly in the `div3` with no `div4`. `build_document` at `ingest/summa.py:97-99` iterates `div4` only, so both are dropped, about 6,149 and 6,912 characters.   - The 21 blank live passages trace to one source pattern. `summa.xml` has 21 paragraphs of the form `<b>Objection 4:</b> On the contrary, ...`, for example `FP_Q29_A2-p5`, `FP_Q32_A3-p5` and `FP_Q48_A5-p6`. New Advent's text of I q. 32 a. 3 reads the same, "Objection 4. On the contrary, It seems that there are more", so the words belong to the edition. `_PART_RE` at line 56 splits at both markers, which leaves "Objection 4" empty. Master already drops the empty piece, because `split_display_passage("")` returns nothing, but the objection's text is then labeled "On the contrary". Adapter output has 17 articles with two "On the contrary" pieces.
  - The 3 tiny live passages are "Eph. 3:5).", "vi)." and ".". Master's splitter already fixes the first two. The "." remains, at III q. 16 a. 3. It is what's left of a translator note `[*The question is hardly apposite in English...]` at `TP_Q16_A3-p2` after apparatus expansion.
  - 4 articles have no "I answer that" marker in the source, `FP_Q68_A2`, `FP_Q74_A3`, `FP_Q91_A4` and `FP_Q117_A2`. In `FP_Q68_A2` the respondeo starts at `-p6` with "I answer with Augustine". 1 article, on dulia, uses "Objection 1." with a period, and it comes out unlabeled.
  - References are `f"Summa Theologiae, {part}, {q}, {a_title}"` at line 106. All pieces of one article share one reference, 3,120 distinct references over 26,792 passages. Part strings are messy, such as "Second Part of the Second Part (Second Part of the Second Part) (Qq. 1–189)".
  - Aquinas's own question prologues, meaning the paragraphs in a `div3` before its first `div4`, are dropped. That is 611 questions and about 297,000 characters, for example "To place our purpose within proper limits, we first endeavor to investigate the nature and extent of this sacred doctrine." Three treatise-level prologues are dropped the same way. The plan doesn't mention these. See Needs Carter.
  - Source structure is clean enough to key on. The `div1` ids are `FP`, `FS`, `SS`, `TP`, `XP` and the appendix, and `div4` ids have the form `FP_Q29_A2`. Bold markers on paragraphs are `Objection N:` 10,527, `Reply to Objection N:` 9,942, `I answer that,` 3,107, `On the contrary,` 3,022 and `Objection N.` 1.
- **Changes:**
  - Replace the flatten-then-regex split with a paragraph walk in `ingest/summa.py`. Add `_article_parts(div) -> list[tuple[str|None, str]]`. Iterate the article's `<p>` children in order. A paragraph whose first child is `<b>` matching `^(Objection \d+[:.]|Reply to Objection \d+:|On the contrary,|I answer that,)` starts a new part, labeled from the bold text only. That makes "Objection 4: On the contrary, ..." an objection whose body starts "On the contrary, ...", which fixes the 21 cases without touching the text. Unmarked paragraphs join the current part. One exception applies. When the current part is "On the contrary" and the article has no bold "I answer that" anywhere, the first unmarked paragraph after the sed contra starts an "I answer that" part. That fixes the 4 unmarked articles. Keep `_split_article` and its tests for the comma-less line-start case until the walk has replaced it, then delete it.
  - Treat a `div3` that contains no `div4` as a one-article question. Parse it with the same walk, and use `chapter_key = anchor("summa", part, q, "article-1")`.
  - Drop any piece with no letters after `clean_text`, which removes the "." piece. Record the drop in metadata for the release report.
  - References. Add `_citation(div4_id, label)`. It maps `FP` to "I", `FS` to "I-II", `SS` to "II-II", `TP` to "III", `XP` to "Suppl." and `AP1`/`AP2` to "Suppl., App. 1/2". It takes q and a numbers from the id and the part suffix from the label, so "Objection N" gives "obj. N", "On the contrary" gives "sed contra", "I answer that" gives "co." and "Reply to Objection N" gives "ad N". The result is "Summa Theologiae I, q. 29, a. 2, obj. 4". `_citation` builds only this base; a part split into several pieces gets its suffix from 1.10c's `piece_reference`, "Summa Theologiae I, q. 29, a. 2, co. (part 1 of 3)" (D5), not from a private counter. Put the clean part name, such as "Second Part of the Second Part", into metadata `part` instead of the current string.
  - Anchors. Use 2.1's structural Summa anchors, built from the part, question and article numbers and the article part (objection N, sed contra, corpus, reply N) as the XML structures them, never from `a_title`. 2.1 already moved the Summa to that scheme, and passage IDs are frozen in 2.1's registry whatever the anchor string (D1). A one-article question takes `article-1` in the same scheme. The paragraph walk changes which text sits under an article-part anchor only inside the articles it repairs, roughly 21 + 4 + 1. The release report lists them.
- **Acceptance checks:**

### 1.8a. ANF editorial strip under rule G

- **Type:** PR
- **Depends on:** 0.4, 2.1, 0.1a, 0.1c, 1.10 (note markup stripping), R4 (whether the Refutation's book "Contents" are authorial)
- **Goal:** Editors' words stop appearing under the Fathers' names. The Elucidations, biographical notices, "Note by the American Editor" sections, translators' introductions, title and translator lines, and bracketed editor comments leave the reader and search. Authenticity judgments inside them move to attribution labels first.
- **Current state:** Counts are from adapter output for the ANF volumes, anf01, 02, 04, 05, 06 and 07. They exclude the NPNF Augustine files, which are 1.8b.
  - Elucidations. 73 passages, 187,682 characters, which matches the plan exactly. They sit in `div`s titled "Elucidation" or "Elucidations", in 38 documents, for example Cyprian's Epistles with 12 passages and 40,666 characters, and the Refutation with 10 and 31,008. `_cf_skippable` in `ingest/common.py:507` skips "elucidations" only as a front-matter title at the exact lowercase value, so chapter-level "Elucidations." with a period and the singular "Elucidation" get through.
  - Translator's biographical notices. 9 passages, 16,687 characters, all in the "Anatolius and Minor Writers" documents.
  - Editor notes. 9 passages, 16,323 characters, with labels "Note by the American Editor", "General Note", "General Notes by the American Editor", "Two Notes by the American Editor" and "Note by the Edinburgh Translator".
  - Translator's introduction. 1 passage, 2,400 characters, in "Treatises Attributed to Cyprian".
  - Refutation "Book N · Contents". 8 passages, 10,365 characters. These wait for R4.
  - Mixed passages. Editorial lines sit at the top of author chapters. Examples are "The Refutation of All Heresies. [Translated by the Rev. J. H. MacMahon, M.A.]" at the start of Book I, "Treatise XI. [Oxford number, xiii. Assigned to a.d. 252 or 257.]" in Cyprian, and "The Banquet of the Ten Virgins; [The idea, and some of the ideas borrowed from the Symposium of Plato, ...]" in Methodius.
  - Bracketed editor comments in body text. With `<note>` elements removed, which is 1.10's job, the Fathers and medieval sources hold 3,367 bracketed spans. 196 of them are 6 words or longer. Most short spans are the translator's supplied words, such as "[of God]" or "[weal]", and must stay. Editorial spans include translator credits, "[See Elucidation VI.]", "[Circa a.d. 238.]", "[A noteworthy estimate of Latin by a Greek.]" and the Twelve Topics comment "[Christ's flesh being incorruptible, transubstantiation cannot be true: the holy food is digested in its material part.]" in Topic IX. Inside notes the count is much higher, 6,991 spans in adapter output, and those go with 1.10's note strip.
  - Class names can't identify editorial text. ANF01 to 06 use generated classes such as `c29` and `c31`. ANF07 uses semantic ones, `BodyText` and `Footnote`. So the strip keys on div titles, div ids and text patterns.
  - Authenticity judgments live in this material. Examples are "Dubious or Spurious Writings." as a Gregory Thaumaturgus part title, "Appendix to the Works of Hippolytus. Containing Dubious and Spurious Pieces", "Treatises Attributed to Cyprian on Questionable Authority", and Methodius's General Note, "The Banquet appears to me a genuine work".
- **Changes:**
  - New module `ingest/editorial.py` with three pieces.
    1. `EDITORIAL_DIV_TITLE`, a regex that matches, after stripping the trailing period and lowercasing, `elucidations?`, `general notes?`, `(two )?notes? by the (american editor|edinburgh translator)`, `general notes? by the american editor`, `translator'?s (biographical notice|introduction|preface)`, `introductory (note|notice).*`, `prefatory notice.*`, `title pages?`, `contents` and `note`. Normalize curly apostrophes before matching. Extend `_cf_skippable` to call it, so `iter_chapters` skips these divs at any depth.
    2. `strip_editorial_lines(paragraphs: list[str]) -> list[str]`. It drops whole paragraphs that are only a title line, a rule line of dashes, a bracketed translator credit `^\[Translated by .*\]$`, or a bracketed date or edition line `^\[(Circa|Oxford number|a\.d\.).*\]$`.
    3. `strip_editor_brackets(text: str, doc_key) -> str`. It removes bracketed spans that match `EDITOR_BRACKET`, a pattern for `See (vol|Elucidation|note)`, `Translated by`, `Circa`, `a\.d\.`, `Oxford`, `American editor`, `Comp\.`, `vol\. [ivx]+`, `p\. \d+` and `Gallandi`. It also removes spans listed by exact sha1 in a reviewed fixture, `ingest/editorial_brackets.json`, and keeps everything else. Build that fixture by exporting all 196 long body spans with file, `<p>` id and text into a review sheet. Carter or the implementer marks each "editor" or "translation". Commit only the "editor" hashes. Short spans stay untouched unless the pattern matches.
  - Call these from `ingest/common.py:_direct_p_text`. Give it an optional `editorial=True` switch, so the Summa and other callers of `_extract_p_text` are unaffected.
  - Removals and judgments go to 2.1's registries, not a file of this item's own (D4). Generate the entries from the build:
    - Each removed div or paragraph that was a live passage gets a `passage` entry in `registry/removals.json`, by live anchor and frozen passage ID, reason `rule-g-editorial`, and a tombstone such as "This passage was an editor's note and was removed because TheoCorpus shows only the authors' own words."
    - Each removed bracket or title line inside a passage that survives gets a `span` entry, with the sha1 of the removed text and an excerpt of at most 120 characters of the public-domain editorial matter.
    - Judgments first. Every entry carries a `judgment` field, filled by the regex `genuine|spurious|dubious|doubtful|interpolat|forg|authentic|attributed` over the full removed text. The implementer copies each flagged judgment into the work's `attribution.editorial_judgments` in `registry/works.json` (2.1), marking `overridden_by_plan: true` where the plan's "Labels for works that stay" overrides it. List the flagged entries in the PR. Together the two files are the audit trail rule G asks for.
  - Refutation "Contents". Leave them untouched until R4 closes. If R4 finds them authorial, relabel them "Book N · Summary" in 1.8c. If not, add `contents` to the matcher in this PR.
  - Fixture. Add `tests/fixtures/thml_editorial.xml`, a 1-work ThML snippet with an Elucidations div, a translator credit paragraph, one editorial bracket and one translation bracket.
- **Acceptance checks:**
